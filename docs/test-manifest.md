# Test manifest

This manifest maps the release-review identifiers to executable tests and gates.
The identifiers are kept verbatim so a missing case cannot be hidden by renaming
or regrouping it.

| Case | Invariant                                                                                                                                                                                                   | Test or gate                                                                                                                                                                                                                            |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1   | A record deletion from a second client races an active scheduled backfill and leaves no sidecar orphan.                                                                                                     | `scripts/real-concurrency.mjs`; 1,000 rows, queued/running pre-delete assertion, independent clients, 20 repetitions, exact raw-sidecar oracle, and full table cleanup. The deterministic harness also covers deletion between batches. |
| R2   | Updates on both sides of the backfill cursor converge to the final record.                                                                                                                                  | `src/component/lifecycle.race.test.ts` — `R2 updates before and after the backfill cursor converge`; 205 rows, 20 repetitions, exact oracle.                                                                                            |
| R3   | An insert after the first backfill batch is indexed. New records cannot sort behind this structural cursor because the scope/table index's implicit creation-time/ID suffix is monotonic.                   | `src/component/lifecycle.race.test.ts` — `R3 insert after the backfill cursor is indexed`; 205 initial rows, 20 repetitions, exact oracle.                                                                                              |
| R4   | Mid-build repair supersedes the old generation; only the new job can set ready.                                                                                                                             | `src/component/lifecycle.race.test.ts` — `R4 repair mid-backfill supersedes the old generation`; 205 rows, 20 repetitions, exact oracle.                                                                                                |
| R5   | A stale batch from create → delete → create cannot write under the dead index ID.                                                                                                                           | `src/component/lifecycle.race.test.ts` — `R5 create delete create leaves no entries under the dead index`; explicitly invokes the stale generation, 20 repetitions, exact oracle.                                                       |
| R6   | Table deletion during backfill removes records, entries, fields, and metadata.                                                                                                                              | `src/component/lifecycle.race.test.ts` — `R6 table deletion during backfill purges all residue`; 205 rows, 20 repetitions.                                                                                                              |
| R7   | Two independent clients racing a unique insert produce one success, one `UNIQUE_CONFLICT`, and one logical row.                                                                                             | `scripts/real-concurrency.mjs`; anonymous local Convex backend, 20 repetitions, independent oracle after each repetition.                                                                                                               |
| R8   | Two independent clients using the same idempotent batch receive identical IDs; changed payload returns `IDEMPOTENCY_MISMATCH`.                                                                              | `scripts/real-concurrency.mjs`; 20 repetitions, independent oracle after each repetition.                                                                                                                                               |
| R9   | Two independent clients patching one `expectedRev` produce one winner and one bounded structured `CONFLICT`.                                                                                                | `scripts/real-concurrency.mjs`; 20 repetitions, independent oracle after each repetition.                                                                                                                                               |
| O1   | A separate oracle recomputes exact normalized sidecars from records.                                                                                                                                        | `assertOracle` in `src/component/lifecycle.race.test.ts` and `scripts/real-concurrency.mjs`; `assertOracle` in `scripts/live-scale.mjs` reads structural records and raw entries through separate host wrappers.                        |
| O2   | Read-only verification detects a deliberately skipped writer update and never mutates sidecars.                                                                                                             | `src/component/runtimeTables.test.ts` — `read-only verification detects a deliberately skipped writer update`; asserts serving before/during verification and safe fallback after failure.                                              |
| O3   | A fault injected after repair but before build verification fails the build and never becomes ready.                                                                                                        | `src/component/lifecycle.race.test.ts` — `O2/O3 a fault after repair is detected by build verification without self-healing`.                                                                                                           |
| C1   | Cursor traversal has exact ascending/descending order and rejects individual scope, index/resource, direction, plan, schema revision, and inner-cursor tampering.                                           | `src/component/runtimeTables.test.ts` — composite traversal and `rejects malformed, oversized, and query-mismatched cursors`; `scripts/live-scale.mjs` traverses both indexes in both directions.                                       |
| C2   | End cursors work; writes between pages do not create gaps/duplicates; dropping an index or changing schema invalidates old cursors.                                                                         | `src/component/runtimeTables.test.ts` — composite pagination, end-cursor assertion, and `invalidates cursors after a result-shaping schema change`.                                                                                     |
| C3   | Malformed and oversized cursors fail with structured `INVALID_CURSOR`; encoded cursors never exceed 8 KiB.                                                                                                  | `src/component/runtimeTables.test.ts` cursor matrix and `src/component/planner.ts` cursor guards.                                                                                                                                       |
| S1   | Every public export with a resource ID rejects a foreign scope; a new export fails the synchronized matrix until covered. Agent requests also use own-property dispatch and a closed runtime operation set. | `src/component/runtimeTables.test.ts` — `keeps the public isolation matrix synchronized with every export`; `src/agent/index.test.ts`.                                                                                                  |
| L1   | `NaN`, infinity, zero, negative, fractional, and over-cap values are crossed with page size, rows read, and bytes read.                                                                                     | `src/component/runtimeTables.test.ts` — `L1 rejects invalid pagination …` matrices.                                                                                                                                                     |
| L2   | Record and generated-entry sizes, indexed text, NFC, field/index counts, constraints, references, rollback, and bounded diagnostics respect component caps.                                                 | `src/component/runtimeTables.test.ts`, `src/component/normalization.test.ts`, `src/component/validation.ts`, and `src/component/data.ts`.                                                                                               |
| L3   | Two independent clients concurrently import the same 5,000 rows in 100-row idempotent batches and store exactly 5,000.                                                                                      | `scripts/real-concurrency.mjs`; final independent record/entry equality and identical IDs per batch.                                                                                                                                    |
| D1   | The exact tarball installs in a clean consumer, excludes all test/fault modules, mounts the component, codegens twice without drift, and executes a mutation and query.                                     | `scripts/consumer-smoke.mjs`; CI `test:consumer`.                                                                                                                                                                                       |

Additional unnumbered gates cover multi-range rejection, achievable index
suggestions, large unfiltered structural pagination, nested agent JSON Schema,
malformed/adversarial agent requests, formatting, lint, typecheck, coverage,
build, and generated-file freshness.
